一键拆表工具 V4.3（tkinter 版，替代 WPS 智能工具箱会员功能）
海上钢琴师出品（不是上海钢琴师，不是上海~不是上海）

用法：选择 Excel 文件 -> 选工作表 -> 选拆分依据列 -> 可选数据起始行 -> 一键拆分
支持两种模式：
  1. 拆到当前工作簿：在原文件内按取值生成多个工作表（原表保留，自动备份）
  2. 拆成多个文件：每个取值生成一个独立 xlsx 到指定文件夹


====================  V4.3 修好了什么（相对 V4.2）  ====================

【致命 · 拆出来的表格在 WPS / Excel 里一片空白】

  本次核心修复。反馈是"拆出来的台账表格是空白的"。
  实际现象：用 WPS 打开拆出来的文件，表头一行是空的、正文里的文字也全都没了，
  只剩下零星几个数字。

  原因：xlsx 是一个"压缩包 + 关系表"的结构。包里有一个
  xl/_rels/workbook.xml.rels，记录着"样式表、共享字符串表、主题分别在哪个文件"。
  这个关系表**本身就在 xl/ 目录下**，所以里面写的路径必须相对 xl/ 目录，例如
  styles.xml、sharedStrings.xml。
  V4.2 错把压缩包里的完整路径直接写了进去（写成 xl/styles.xml），
  被解析出来就变成了 xl/xl/styles.xml —— 这个文件根本不存在。

  结果：WPS / Excel 按关系表去找，找不到字符串表，于是
  **所有文字单元格（Excel 内部用"共享字符串表"存文字）全部显示为空白**，
  数字还能显示（数字是直接存在单元格里的）。这就是你看到的"空白表"。

  为什么之前没测出来：openpyxl（我做测试用的库）读共享字符串是**直接按固定路径**
  去找的，不查关系表，所以它照样能读出文字，测试全绿；只有真正的 Office 才会暴露。
  这是个教训 —— V4.3 新增了一项**出包自检**：每写一个文件都检查
  "关系表里每一个目标都必须落在真实存在的部件上"，不合法立刻报错中止，
  绝不再把 WPS 打不开的文件交出去。同时新增专门的测试脚本盯这一类问题。

  另外：共享字符串表补回了 XML 声明头（源文件里有，V4.2 切片时丢掉了；
  规范上可选，但补上更保险）。


====================  V4.2 修好了什么（相对 V4.1）  ====================

【重要 · 大表格（台账类）一打开就卡死】

  拿真实的 341MB 台账（16.1 万行 × 413 列，6650 万个单元格）实测，
  定位到四个互相独立的原因，全部修掉：

  (1) 选文件后读工作表名
      旧版用 openpyxl 完整加载一遍工作簿只为拿几个工作表名，
      341MB 的台账要 8.8 秒，而且全卡在界面主线程上。
      -> 改成只读 workbook.xml 里的一小段，实测 0.003 秒。

  (2) 选工作表后统计真实行列数
      旧版在主线程上扫全表，要 64 秒，界面完全冻住。
      -> 改成后台线程执行，并把"整表正则扫描"改成"逐行只看最后一个单元格"，
         降到 8 秒；同一文件第二次打开直接走缓存（0 秒）。
         实测主线程阻塞 0.002 秒，后台扫描期间事件循环转了 623 次。

  (3) 选列后统计该列有哪些取值
      旧版走 openpyxl 只读迭代，即使只要一列，也要把每行 413 个单元格全解析一遍
      （单行 1.7 毫秒，16 万行要 278 秒），而且纯 Python 解析会长时间占住 GIL，
      界面照样不响应。
      -> 改成定向 XML 引擎，只解析目标那一列，8 秒，且放在后台线程。

  (4) 【最致命】点"开始拆分"后卡死
      旧版用 openpyxl 普通模式加载工作簿，要给 6650 万个单元格每个都建一个对象，
      实测要占约 4.7GB 内存，而机器当时只有 3.6GB 可用 —— 程序开始疯狂读写
      硬盘换页，表现就是"卡死"（其实是在硬撑，可能几十分钟都不出结果）。
      -> 「拆成多个文件」改走**流式 XML 通道**：边解压边按行切块，
         只把需要的行落到临时文件，再逐个拼装输出文件。
         内存占用与文件大小基本无关，341MB 台账全程峰值 507MB。

【重要 · 「拆到当前工作簿」不再让人白等】
  这个模式必须把整张表读进内存，6650 万格是装不下的。
  V4.2 会在开始前先做内存体检，装不下就立刻明确告诉你"这个表太大，
  请改用「拆成多个文件」"，而不是让你等一个永远不来的结果。

【大表拆出来的文件也正确了】
  - 共享公式（Excel 为了省体积，把一列公式存成"一个主公式 + 一堆引用"）
    在拆行后会被拆散到不同文件，照搬会让 Excel 报"文件已损坏"。
    V4.2 会就地把它展开成普通公式。
  - 拆出的文件不再继承源表的"行隐藏"状态。台账常常整表处于筛选状态
    （每一行都带隐藏标记），拆出来后筛选条件已经没了，如果还保留隐藏标记，
    用户会看到一片折叠的行、以为又丢数据了。
  - 额外保留：自动筛选范围（按新数据区重排）、数据有效性（重排范围）、
    超链接（内部/外部都重排，外部链接会重建关系文件）。
  - 修掉一个坐标系搞混的 BUG：超链接 A3 曾被写成 C1。

【输出体积大幅变小】
  源台账的共享字符串表是 33MB / 111 万条。V4.2 做了"子集化"：
  **保持条目总数和索引位置完全不变**，只把本文件没引用到的条目置空，
  所以不用改写任何一个引用值。43 个文件合计从 421MB 降到约 327MB。


====================  V4.1 修好了什么（相对 V4）  ====================

【重要 · 拆大表格报「IndexError: list index out of range」】
  原因：xlsx 里每个单元格的样式，存的是一串"编号"（第几号字体、第几号填充、
  第几号对齐…），这些编号对应的是**源文件**里的样式清单。
  V4 直接把编号抄进了新文件，但「拆成多个文件」时每个新文件都是全新的空工作簿，
  它的样式清单里只有默认的那一两条。编号一查就越界了 —— 于是保存时报 IndexError。
  V4.1 改成按"样式内容"逐个搬进新文件，并让程序自己登记编号，彻底解决。

【报错信息不再看不出原因】
  弹窗会显示「外层调用位置 + 内层出错点」的首尾摘要，并把**完整**错误信息写到
  源文件旁边的「一键拆表-错误日志.txt」，方便直接发回来定位问题。


====================  V4 修好了什么（相对 V3）  ====================

【重要 · 列变少 / 行变少】
  xlsx 文件里有一个 <dimension> 标签，用来"声明"表格有多大。很多系统导出的文件里，
  这个声明和实际数据对不上（比如声明 200 列，实际只有 150 列）。V3 直接信了这个声明：
    - 界面下拉框显示 200 列，拆出来的文件只有 150 列  -> "列变少"
    - 声明行数比实际少时，多出来的行被静默丢掉     -> "行变少"
  V4 起不再信任这个声明，改为直接扫描表格 XML 统计真实存在的行列，
  界面、预览、实际拷贝三处口径完全一致。

【数据安全】
  - 「拆到当前工作簿」保存前，会自动把原文件备份一份：原名.backup.xlsx

【速度】
  - 「拆成多个文件」时源工作簿只加载一次（V3 是每个分组都重新加载一遍）
  - 拷贝时只遍历真正需要的行

【输出文件】
  - 不再把原工作簿里的其它工作表带进每一个输出文件（V3 会带）
  - 文件名自动去重，不会互相覆盖
  - 补齐 Windows 非法字符（V3 漏了 < > " |），并限制长度

【格式保留】
  - 合并单元格全部按行号保留（V3 只保留第 1 行的）
  - 条件格式的行号会跟着数据重排
  - 冻结窗格按数据起始行校正

【易用】
  - 列下拉框不再被 512 列上限截断（最多支持 16384 列）
  - 拆分结果会明确告诉你：有多少行因为拆分依据列是空的而被跳过
  - 预览区会显示源表的真实行列数
  - 源文件是 .xlsm（启用宏）时会提示宏不会保留


====================  相对 V2 的功能  ====================

  - 可指定数据起始行：第 1 行 ~ 起始行-1 视为表头，原样保留在每个拆分结果顶部；
    拆分扫描从起始行开始
  - 可选是否把空白行拆为「(空白)」表/文件


====================  使用建议  ====================

  - 大表第一次选工作表 / 选列时，后台统计需要十几秒，属正常现象，
    界面不会卡住，状态栏会显示进度和已用时间。同一文件再操作会明显更快（走缓存）。
  - 341MB 这一档的台账，拆成 43 个文件大约需要 2 分钟；期间界面可以正常操作。
  - 「拆到当前工作簿」会重写源文件，虽然会自动备份，但建议对重要文件先手动另存一份。
    表特别大时请优先用「拆成多个文件」。
  - 源文件是 .xlsm（启用宏）时：**两种拆分模式都不会保留宏**（输出的是全新的 .xlsx），
    程序会提示。需要宏请先把源文件另存为 .xlsx 再拆。
  - 拆分依据列最好是没有空白的列；有空白的行默认不拆出，可勾选「空白行也拆出」。
  - 拆分过程会在输出文件夹所在盘产生一个临时文件（`一键拆表-*.spool`），
    正常结束会自动删除；如果程序被强制关闭，可以手动删掉它。
  - 如果拆到一半失败，先去源文件所在文件夹看「一键拆表-错误日志.txt」，
    里面记录了完整的出错位置。


====================  自检  ====================

  如果怀疑程序有问题，可以运行自检：
      一键拆表-V4.3.exe --selftest 报告.txt
  程序会把环境与核心功能的检查结果写进 报告.txt（最后一行 RESULT=PASS 表示正常）。
