一键拆表工具 V4.5（tkinter 版，替代 WPS 智能工具箱会员功能）
海上钢琴师出品（不是上海钢琴师，不是上海~不是上海）

用法：选择 Excel 文件 -> 选工作表 -> 选拆分依据列 -> 可选数据起始行 -> 一键拆分
支持格式：.xlsx / .xlsm / .xlsb
支持两种模式：
  1. 拆到新工作簿：源文件不动，另存为「原名-拆分.xlsx」，原有工作表一并保留
  2. 拆成多个文件：每个取值生成一个独立 xlsx 到指定文件夹


====================  V4.5 修好了什么（相对 V4.4）  ====================

【重要 · 支持 xlsb（二进制工作簿）】

  现象：选 .xlsb 文件时，程序直接弹「无法打开文件」。
  原因：xlsb 是 BIFF12 **二进制**格式，包里的部件叫 xl/workbook.bin、
  xl/worksheets/sheet1.bin、xl/sharedStrings.bin；而本工具整套引擎是建立在
  「ZIP + XML」上的，找的是 xl/workbook.xml —— 找不到就报打不开。
  二进制格式没法用 XML 引擎解析，这是硬约束，只能换路子。

  修法：检测到 xlsb 时，先调用**本机 WPS 表格 / Microsoft Excel** 的自动化接口，
  让它自己把文件另存为 xlsx，再走原来的拆分流程。
  因为是 Office 自己另存的一份，格式、公式、合并单元格、列宽行高、条件格式、
  数据验证**全部原样保留**，保真度比任何纯 Python 方案都高。

  你要知道的几件事：
  - 转换由 Office 完成，程序只是发指令，所以**机器上必须装有 WPS 或 Excel**
    （WPS 个人版就够，绿色版/精简版如果没注册 COM 组件则不行）。
  - 大文件要等一会儿：实测 180MB 的 xlsb 转换耗时约 70 秒（含启动 WPS），
    期间状态栏显示已用时间，**请不要手动关闭 WPS 窗口**。
  - 转换结果会缓存到：
        %LOCALAPPDATA%\一键拆表\xlsb缓存\
    同一个文件第二次打开就直接用缓存，不用再等。源文件一改动，缓存自动失效。
    这个目录可以随时手动清空（不影响程序）。
  - 扩展名被改过的 xlsb（比如明明是 xlsb 却叫 .xlsx）也能识别，程序会看包里的
    部件名来判断，不会漏判。

【重要 · 只拆选定的表，其他子表不再被动】

  现象：源工作簿里明明有好几张表，我只想拆其中一张，结果拆完之后别的表
  被弄坏了（图表、图片、数据透视表丢失）。
  原因：旧的「拆到当前工作簿」是直接把源文件整个重写一遍 —— openpyxl 保存时
  会重新生成整个工作簿，源文件里其他工作表的图表、图片、透视表、切片器这些
  部件会丢。
  修法：这个模式改成**源文件只读、结果另存**：
  - 源文件一个字节都不改（连自动备份都不再需要了，不会再多出 .backup.xlsx）；
  - 在源文件所在目录生成「<原名>-拆分.xlsx」；
  - 新文件里 = 源工作簿的全部原有工作表（原样搬过去）+ 新拆出来的若干工作表。
  界面文案也改成了「拆到新工作簿（源文件不动…）」，选项名字变了是正常的。

  一句话记法：
      源文件永远不动；拆出来的东西都进新文件。

【细节】

  - xlsb 源文件的输出命名用**原始**文件名（如「26年9月终端台账-事业部描述-混凝土.xlsx」），
    不会用临时转换出来的文件名；出错日志也写在源文件旁边。
  - 新文件是 .xlsx 格式，所以 xlsm / xlsb 里的宏（VBA）不会保留。
  - 自检报告里新增了 comtypes 与本机 Office COM 注册情况的检查项，方便排查
    xlsb 转换不可用的问题。


====================  V4.4 修好了什么（相对 V4.3，仍然有效）  ====================

【重要 · 公式拆出来引用错行】共享公式平移的锚点用错了行号；普通公式在两种模式下
  都不平移。V4.4 两条通道统一按「旧行号 -> 新行号」平移，并新增三个回归用例钉住。

【重要 · 取值恰好是"(空白)"时会静默丢数据】改为合并进同一组，一行都不丢。

【防呆 · 拆分中切换工作表后按钮被误恢复】【体验 · 详细进度不再被计时器盖掉】
【健壮 · 输出文件名长度限制、check_package_rels 读不开时不再静默放行】


====================  V4.3 修好了什么（相对 V4.2，仍然有效）  ====================

【致命 · 拆出来的表格在 WPS / Excel 里一片空白】
  根因：xlsx 是「压缩包 + 关系表」的结构，xl/_rels/workbook.xml.rels 里写的路径
  必须相对 xl/ 目录，V4.2 错把完整路径写了进去，WPS / Excel 按关系表去找样式表、
  字符串表全部落空，所有文字单元格显示为空白。V4.3 修复并新增出包自检。


====================  使用建议  ====================

  - 大表第一次选工作表 / 选列时，后台统计需要十几秒，属正常现象，
    界面不会卡住，状态栏会显示进度和已用时间。同一文件再操作会明显更快（走缓存）。
  - 「拆到新工作簿」会把整个工作簿读进内存，超大的表（几千万单元格）会被
    内存体检拦下并提示改用「拆成多个文件」—— 那条通道是流式的，多大都不怕。
  - 源文件是 .xlsm / .xlsb（可能含宏）时：两种拆分模式都不保留宏，程序会提示。
  - 拆分依据列最好是没有空白的列；有空白的行默认不拆出，可勾选「空白行也拆出」。
  - 拆分过程会在输出文件夹所在盘产生一个临时文件（`一键拆表-*.spool`），
    正常结束会自动删除；如果程序被强制关闭，可以手动删掉它。
  - 如果拆到一半失败，先去源文件所在文件夹看「一键拆表-错误日志.txt」，
    里面记录了完整的出错位置。

  【V4.4 补充】
  - 带公式的表格拆分后，公式会跟着行号平移，引用仍然指向"同一行"的数据；
    数组公式（{=...}）保持原样不平移（其缓存值会一并带过去）。

  【V4.5 补充】
  - 拆 xlsb 之前建议先在 WPS 里确认文件能正常打开；转换失败时程序会提示，
    也可以自己在 WPS 里「另存为」xlsx 之后再用本工具。


====================  自检  ====================

  如果怀疑程序有问题，可以运行自检：
      一键拆表-V4.5.exe --selftest 报告.txt
  程序会把环境与核心功能的检查结果写进 报告.txt（最后一行 RESULT=PASS 表示正常）。
  V4.5 的自检额外报告 comtypes 版本与本机 Office COM 注册情况（xlsb 转换的前提）。
