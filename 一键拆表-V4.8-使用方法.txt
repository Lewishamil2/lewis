一键拆表工具 V4.8（tkinter 版，替代 WPS 智能工具箱会员功能）
海上钢琴师出品（不是上海钢琴师，不是上海~不是上海）

用法：选择 Excel 文件 -> 选工作表 -> 选拆分依据列 -> 可选数据起始行 -> 一键拆分
支持格式：.xlsx / .xlsm / .xlsb
支持两种模式：
  1. 拆到新工作簿：源文件不动，另存为「原名-拆分.xlsx」，原有工作表一并保留
  2. 拆成多个文件：每个取值生成一个独立 xlsx 到指定文件夹
     （默认把源文件的其他工作表也一并带进每个文件）


====================  V4.8 修复（相对 V4.7）  ====================

  1. 拆成多个文件时，输出文件夹已有同名文件会自动加序号；写入时也采用独占创建，
     避免并发情况下覆盖原文件。
  2. 保留其他工作表时，保留工作簿的命名区域，并校正工作表局部名称的作用域序号。
     如果命名区域引用的是被拆表的原始数据行，拆分后仍应人工核对引用范围。
  3. 相对路径的外部超链接（如 ../manual.pdf）不再被误判为损坏的包。
  4. 选择不支持的旧版 .xls 或无法读取的新文件时，会清除上一文件的可拆状态，
     不会再把上一文件的数据当作新文件拆分。
  5. 被拆分工作表上的图片、图表会按锚点所在行分配到对应结果；表头区域的图片
     会出现在每个结果中。原有其他工作表的图片、图表、批注继续保留。


====================  V4.7 修好了什么（相对 V4.6）  ====================

  这一版是自查代码时发现并修掉的隐患，其中第 1 条是真会出事的那种。

【重要 · 要保留的那张表带图片/图表时，输出文件会坏】

  场景：源工作簿里除了要拆的台账，还有一张带 logo 图片（或图表、批注）的表，
  你勾了「保留源文件的其他工作表」。
  结果：拆出来的文件在 WPS 里打不开，提示文件已损坏 —— 整个拆分白做。
  原因：程序只把那张表的 XML 搬了过去，**没搬它引用的图片、绘图、批注部件**
  （它们在包里是分开存的：xl/drawings/*、xl/media/*、xl/comments* 等）。
  包里的关系表指向了不存在的部件，Office 直接判为非法包。
  修法：按「工作表 -> 它的关系表 -> 关系表里引用的部件」递归把整串依赖都搬过来，
  并把源文件里对这些部件的类型声明一并带上。
  实测：带图片的说明页现在能完整保留，包结构自检通过。

【防呆 · 源文件被改动后，程序会用旧数据拆】

  场景：你在程序里选了 xlsb（程序后台转换并缓存），中途又去 WPS 里保存了这个
  xlsb、或者重新下载了一份。回到程序里继续拆 —— 它会拿**旧的转换结果**去拆，
  拆出来的数据是老的，而且完全看不出来。
  修法：点「一键拆分」时会重新核对源文件是否还是当初那份，
  变了就明确提示"请重新选择文件"，不再闷头拆旧数据。
  另外，如果转换缓存被清理掉了，也会提前提示，不会等到拆到一半才报文件不存在。

【体验】

  - 选中旧版 .xls 文件时，不再只弹一句"无法打开文件"，
    而是直接告诉你"请先另存为 xlsx 或 xlsb"。
  - 文件的"文档属性"里，工作表数量与实际一致了（以前恒显示 1 个）。
  - 复制超大部件时统一启用 zip64（和之前工作表那一处对齐），
    避免同一类"文件太大"的报错换个地方再冒出来。

  【顺便说明】转换 xlsb 时程序**不会碰源文件**。
  实测：转换前后源文件的字节数和修改时间完全一致（读取用的是只读方式）。


====================  V4.6 修好了什么（相对 V4.5，仍然有效）  ====================

【重要 · 筛选按钮跑到数据行上了】
  三行表头、从第 4 行开始拆，筛选按钮却出现在第 4 行（第一行数据上）。
  原因是程序拿「数据起始行」当成了筛选按钮所在行 —— 而 autoFilter 的 ref
  起始行就是按钮所在行。已改为「表头最后一行」，并且不再丢掉源表的
  筛选条件（比如某列筛了"专案二室"）和 WPS 扩展属性。

【重要 · 拆出来的文件里看不到源文件的其它工作表】
  新增选项「保留源文件的其他工作表」，**默认勾选**。
  每个输出文件 = 拆出的数据表（排第一）+ 源文件里其它工作表（按原顺序跟在后面）。
  取消勾选则回到旧行为（每个文件只有拆出的那一张表）。


====================  V4.5 修好了什么（相对 V4.4，仍然有效）  ====================

【支持 xlsb（二进制工作簿）】选 .xlsb 不再报错，程序先调用本机 WPS / Excel
  把它另存为 xlsx 再拆。180MB 的文件首次转换约 70~150 秒；转换结果缓存在
  %LOCALAPPDATA%\一键拆表\xlsb缓存\，第二次打开直接用缓存，源文件一改缓存失效。
  （缓存目录可以随时手动清空，不影响程序。）

【只拆选定的表，其他子表不再被动】「拆到当前工作簿」改为「拆到新工作簿」：
  源文件一个字节都不改，结果另存为「<原名>-拆分.xlsx」，原有工作表全部带过去。

【大表拆到一半失败】工作表 XML 超过 zipfile 的 2GB 硬限制会抛
  RuntimeError: File size too large。已改为始终按 zip64 写。


====================  V4.4 / V4.3 修好了什么（仍然有效）  ====================

【V4.4】共享公式 / 普通公式拆出来引用错行 —— 统一按「旧行号 -> 新行号」平移；
        取值恰好是"(空白)"时不再静默丢数据。
【V4.3】拆出来的表格在 WPS / Excel 里一片空白 —— 关系表里的路径写多了一层
        xl/，导致找不到样式表和字符串表；已修，并新增出包结构自检。


====================  使用建议  ====================

  - 大表第一次选工作表 / 选列时，后台统计需要十几秒，属正常现象，
    界面不会卡住，状态栏会显示进度和已用时间。同一文件再操作会明显更快（走缓存）。
  - 「数据起始行」填**第一行数据**的行号。前三行是表头就填 4；
    程序会把第 1 行 ~ 起始行-1 原样保留，并把筛选按钮放在第「起始行-1」行。
  - 「拆到新工作簿」会把整个工作簿读进内存，超大的表（几千万单元格）会被
    内存体检拦下并提示改用「拆成多个文件」—— 那条通道是流式的，多大都不怕。
  - 源文件是 .xlsm / .xlsb（可能含宏）时：两种拆分模式都不保留宏，程序会提示。
  - 拆分依据列最好是没有空白的列；有空白的行默认不拆出，可勾选「空白行也拆出」。
  - 拆分过程会在输出文件夹所在盘产生一个临时文件（`一键拆表-*.spool`），
    正常结束会自动删除；如果程序被强制关闭，可以手动删掉它。
  - 如果拆到一半失败，先去源文件所在文件夹看「一键拆表-错误日志.txt」，
    里面记录了完整的出错位置。
  - 带公式的表格拆分后，公式会跟着行号平移，引用仍指向"同一行"的数据；
    数组公式（{=...}）保持原样不平移（其缓存值会一并带过去）。


====================  自检  ====================

  如果怀疑程序有问题，可以运行自检：
      一键拆表-V4.8.exe --selftest 报告.txt
  程序会把环境与核心功能的检查结果写进 报告.txt（最后一行 RESULT=PASS 表示正常）。
  自检会报告 comtypes 版本与本机 Office COM 注册情况（xlsb 转换的前提）。
