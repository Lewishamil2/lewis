一键拆表工具 V4.4（tkinter 版，替代 WPS 智能工具箱会员功能）
海上钢琴师出品（不是上海钢琴师，不是上海~不是上海）

用法：选择 Excel 文件 -> 选工作表 -> 选拆分依据列 -> 可选数据起始行 -> 一键拆分
支持两种模式：
  1. 拆到当前工作簿：在原文件内按取值生成多个工作表（原表保留，自动备份）
  2. 拆成多个文件：每个取值生成一个独立 xlsx 到指定文件夹


====================  V4.4 修好了什么（相对 V4.3）  ====================

【重要 · 公式拆出来引用错行】本次核心修复，两个问题、一套修法。

  (1) 共享公式平移的锚点用错了行号。
      现象：拆出来的单元格里，公式引用的还是**旧行号**。比如源表第 5 行的
      =B5*2，挪到新文件第 3 行后仍然是 =B5*2 —— 而 B5 在新文件里根本不是
      它那一行。更隐蔽的是：单元格里还带着旧的缓存值，打开时数值看着是对的，
      一旦编辑触发重算，值就变了 —— "看着对、一改就错"。
      根因：V4.3 展开共享公式时只拿到旧行号，把共享公式展开成旧坐标系下的
      普通公式就直接写出了。
      修法：展开时同时传入新行号，master 和依赖单元格的公式一律按
      「旧行号 -> 新行号」平移后再写出。

  (2) 普通公式（非共享）在两种模式下都不平移。
      V4.3 里流式通道和 openpyxl 通道都直接照抄公式串，行号压缩后引用
      同样指错行（而且和共享公式的行为还不一致）。V4.4 两条通道统一：
      公式一律按旧行号 -> 新行号平移（复用 openpyxl 自带的 Translator）。

  另外一个连带问题也修了：master 行本身被跳过（拆分列空白等）时，
  V4.3 的依赖单元格会因为查不到 master 而把公式整个丢掉；
  V4.4 会先学习 master 的公式正文再跳过（_learn_shared_formulas）。

  自检里新增了三个回归用例钉住这一类问题（共享公式平移、普通公式平移、
  "(空白)"冲突），见文末「自检」。

【重要 · 取值恰好是"(空白)"时会静默丢数据】
  勾选「空白行也拆出」后，空白行会以"(空白)"为名分组。如果拆分列里恰好
  有一行的真实取值就是"(空白)"，V4.3 的直接赋值 groups['(空白)'] = empties
  会把这一组**覆盖掉** —— 这些行从所有输出里消失，而且统计上看不出来。
  V4.4 改为合并进同一组（数据行在前，空白行跟在后面），一行都不丢。

【防呆 · 拆分中切换工作表后按钮被误恢复】
  拆分进行中用户切换了工作表（界面不阻塞），等拆分结束按钮会被无条件
  恢复，此时列还没选，点下去会把整列判成空白。V4.4：do_split 先校验
  已选中列；拆分结束后只在确实有选中列时才恢复「一键拆分」按钮。

【体验 · 详细进度不再被计时器盖掉】
  V4.3 状态栏的"读取源表数据…（已处理 N 行）"会被"已用 X 秒"计时器
  每 80ms 覆盖一次，基本看不见。V4.4 进度消息会同步进计时器文本。

【健壮 · 两处小修】
  - 输出文件名把「基础名 + 取值」总长一起限制：V4.3 只在重名分支截断，
    源文件名很长时首个文件名仍可能超 Windows 260 字符上限，写不出去。
  - check_package_rels 对"输出包本身读不开"（zip 损坏）不再静默放行，
    会作为问题报出来。
  - 删除死代码（split_to_files_stream 里从未使用的 notes、界面里从未
    读取的 _col_cache）；「拆到当前工作簿」的列数口径与界面/流式通道对齐。


====================  V4.3 修好了什么（相对 V4.2）  ====================

【致命 · 拆出来的表格在 WPS / Excel 里一片空白】
  根因：xlsx 是一个"压缩包 + 关系表"的结构。xl/_rels/workbook.xml.rels 里
  写的路径必须相对 xl/ 目录，V4.2 错把完整路径写了进去（xl/styles.xml），
  WPS / Excel 按关系表去找样式表、字符串表全部落空，所有文字单元格显示
  为空白。V4.3 修复并新增出包自检 check_package_rels()。


====================  使用建议（沿袭 V4.3，未变的部分不重复）  ====================

  - 大表第一次选工作表 / 选列时，后台统计需要十几秒，属正常现象，
    界面不会卡住，状态栏会显示进度和已用时间。同一文件再操作会明显更快（走缓存）。
  - 341MB 这一档的台账，拆成 43 个文件大约需要 2 分钟；期间界面可以正常操作。
  - 「拆到当前工作簿」会重写源文件，虽然会自动备份，但建议对重要文件先手动另存一份。
    表特别大时请优先用「拆成多个文件」。
  - 源文件是 .xlsm（启用宏）时：两种拆分模式都不会保留宏，程序会提示。
  - 拆分依据列最好是没有空白的列；有空白的行默认不拆出，可勾选「空白行也拆出」。
  - 拆分过程会在输出文件夹所在盘产生一个临时文件（`一键拆表-*.spool`），
    正常结束会自动删除；如果程序被强制关闭，可以手动删掉它。
  - 如果拆到一半失败，先去源文件所在文件夹看「一键拆表-错误日志.txt」，
    里面记录了完整的出错位置。

  【V4.4 补充】
  - 带公式的表格拆分后，公式会跟着行号平移，引用仍然指向"同一行"的数据；
    数组公式（{=...}）保持原样不平移（其缓存值会一并带过去）。


====================  自检  ====================

  如果怀疑程序有问题，可以运行自检：
      一键拆表-V4.4.exe --selftest 报告.txt
  程序会把环境与核心功能的检查结果写进 报告.txt（最后一行 RESULT=PASS 表示正常）。
  V4.4 的自检额外覆盖：共享公式平移、普通公式平移、"(空白)"取值冲突三个回归用例。
